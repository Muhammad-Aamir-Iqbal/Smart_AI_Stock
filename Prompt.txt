To build **SmartStock AI** reliably without overloading an LLM or causing hallucinations, the application needs to be split into distinct, modular building blocks.

Below is a complete, multi-stage prompt sequence. You can feed these prompts one by one into your AI coding assistant (Cursor, GitHub Copilot, ChatGPT, etc.) to build the app step-by-step.

### Phase 1: Project Setup & Core Environment

**Prompt 1.1: Project Structure and Setup**

> Create a clean, modular Python project structure for a Streamlit web application named `SmartStock AI`.
> * Project layout:
> * `app.py` (Main entry point)
> * `pages/` (`1_🏠_Home.py`, `2_📊_Demand_Forecasting.py`, `3_📦_Smart_Inventory_RAG.py`, `4_👥_About_Us.py`)
> * `modules/` (`data_loader.py`, `forecaster.py`, `rag_engine.py`, `calendar_utils.py`)
> * `requirements.txt`
> * `.env`
> 
> 
> * Provide a `requirements.txt` file containing: `streamlit`, `pandas`, `numpy`, `torch`, `transformers`, `hijri-converter`, `faiss-cpu`, `langchain`, `langchain-community`, `langchain-groq`, `sentence-transformers`, `openpyxl`, `plotly`.
> * Include basic setup code in `app.py` configuring a modern, e-commerce themed UI using custom CSS (sleek dark/light theme with primary colors `#00C853` and `#1E88E5`).
> 
>

### Phase 2: Data Preprocessing & Calendar Conversion

**Prompt 2.1: Data Ingestion & Auto-Formatting (`data_loader.py`)**

> Write a Python module `modules/data_loader.py` that handles multi-format file uploads (CSV, Excel `.xlsx`/`.xls`, JSON, SQLite `.db`).
> Function requirements:
> 1. `load_raw_data(uploaded_file)`: Automatically detects file extension and loads it into a Pandas DataFrame.
> 2. `standardize_sales_data(df)`: Maps raw user columns (e.g., "Item Name", "Qty Sold", "Sale Date", "Price") into unified schema columns: `['date', 'product_id', 'product_name', 'category', 'units_sold', 'stock_on_hand']`. Provide clear exception handling and sensible defaults for missing columns.
> 3. Return the clean DataFrame along with a processing status report.
> 
> 

**Prompt 2.2: Dual Calendar & Holiday Feature Integration (`calendar_utils.py`)**

> Write a Python module `modules/calendar_utils.py` that processes dates and integrates Gregorian and Islamic (Hijri) calendars.
> Function requirements:
> 1. `get_next_week_dates(start_date=None)`: Generates a 7-day date range starting from next Monday.
> 2. `enrich_calendar_features(df)`: Takes a DataFrame with a `date` column and adds:
> * `day_of_week`, `is_weekend`, `month`
> * `hijri_day`, `hijri_month`, `hijri_year` using the `hijri-converter` library.
> * Boolean indicator `is_ramadan` or `is_eid` based on Hijri months (9th month for Ramadan, 10th and 12th for Eids).
> 
> 
> 3. Provide a helper function `convert_gregorian_to_hijri_string(date_obj)` for displaying dates neatly in the Streamlit UI.
> 
> 

---

### Phase 3: AI Time-Series Demand Forecasting Model

**Prompt 3.1: Pretrained Time-Series Model Engine (`forecaster.py`)**

> Write a Python module `modules/forecaster.py` using Hugging Face Transformers to forecast next-week sales demand.
> Technical details:
> 1. Use a lightweight time-series model or zero-shot forecaster like `ibm-granite/granite-timeseries-ttm-r3` or a fallback `Chronos`/`Prophet` pipeline.
> 2. Function `predict_next_week_sales(historical_df, forecast_days=7)`:
> * Group sales data by `product_id` and `date`.
> * Pass the daily sales time-series through the model.
> * Multiply baseline predictions by calendar modifiers (e.g., +25% boost if `is_ramadan` or `is_eid` is true).
> 
> 
> 3. Output a summarized DataFrame containing:
> * `product_id`, `product_name`, `category`, `predicted_units_next_week`, `sales_rank`, `reorder_recommended` (True if `predicted_units` > `stock_on_hand`).
> 
> 
> 4. Ensure the function runs safely on CPU with proper caching using `@st.cache_data`.
> 
> 

---

### Phase 4: RAG & Smart Inventory Engine

**Prompt 4.1: FAISS Vector Store & Groq LLM RAG Setup (`rag_engine.py`)**

> Write a Python module `modules/rag_engine.py` using LangChain, FAISS, Sentence Transformers, and Groq API (`langchain-groq`).
> Requirements:
> 1. Function `build_inventory_knowledge_base(sales_summary_df, stock_df)`:
> * Converts product sales metrics, current stock, predicted demand, and reorder alerts into formatted string documents.
> * Embeds these documents using `sentence-transformers/all-MiniLM-L6-v2`.
> * Stores them in a local FAISS vector store.
> 
> 
> 2. Function `query_smart_inventory_rag(user_query, faiss_store, groq_api_key)`:
> * Retrieves top-k relevant context chunks from FAISS based on the store manager's prompt.
> * Connects to Groq using model `llama-3.1-8b-instant` or `mixtral-8x7b-32768`.
> * Returns actionable inventory advice (e.g., "Which products are at risk of stockouts during Ramadan?", "Generate a purchase order list").
> 
> 
> 
>
